# 介绍 WallGraph 与 PlanRegions

[English](promotion.md) · [交互示例](https://crown-sports.github.io/planregions/) · [比较使用指南](comparison.zh-CN.md)

以下介绍可以用于项目页、版本发布说明或开发者分享，重点说明工具能帮助谁、解决什么问题。它们是可采用的宣传材料，不代表已经投放广告、获得用户背书或提升识别精度。

## 30 秒介绍

> 模型更新以后，哪些房间悄悄变了？一处细小的墙体缺口，可能让两个区域连成一个，或让内部空间连到外部。PlanRegions 比较对齐的实例图，用本地可视化报告标出合并、分裂和消失，让你直接检查受影响的像素，再决定哪些地方需要复核。它也能从二值墙体掩码提取带孔洞、具有精确像素面积的区域。先体验程序生成的浏览器示例，再带上自己的标签图。

链接：[交互示例](https://crown-sports.github.io/planregions/) · [PlanRegions 源码](https://github.com/crown-sports/planregions) · [v0.3.0 发布](https://github.com/crown-sports/planregions/releases/tag/v0.3.0)

## 一段可用于发布的介绍

**一个像素，两个房间就合并了。**

在程序生成的 20 × 30 布局中，94 个墙体像素移除一个，前后墙体掩码 IoU 仍有 98.94%。移除内墙像素，两个区域就会合并；移除外墙像素，IoU 相同，一个区域却会因为连接到外部而被排除。这是几何示例，不是训练模型的精度评测。

PlanRegions 把这种空间变化直接展示出来。比较同一原图像素网格上的两张整数实例图，生成自包含 HTML 报告，查看区域对应组，以及像素进入或离开排除空间的情况。两次输出的 ID 可以不同，也可以用 `--fail-on merge disappeared` 让流水线提示复核。

[浏览器示例](https://crown-sports.github.io/planregions/) 无需安装或下载模型。用 PlanRegions v0.3.0 检查自己的输出：

```bash
planregions compare --before runs/before/labels.npz \
  --after runs/after/labels.npz --output runs/review/changes.json \
  --html-output runs/review/changes.html
```

比较报告描述观察到的变化。合并可能来自主动修改，消失也不能单独证明识别错误；判断正确性仍需要独立真值。

## 开发者为什么可能需要它们

分割模型输出像素，应用还需要可用的几何结果；模型升级后，开发者也需要检查具体空间发生了什么。这两个项目用明确的输入输出约定，连接模型结果、几何处理和人工复核。

[WallGraph v0.1.2](https://github.com/crown-sports/wallgraph/releases/tag/v0.1.2) 将墙体预测整理为原图坐标中的折线、交点与闭环。模型适配器和几何处理阶段可以分别替换，适合把已有墙体模型接入图纸复核界面或下游几何流水线。项目提供私有数据训练、ONNX 导出与评测说明，也记录复现中遇到的数值局限。

[PlanRegions v0.3.0](https://github.com/crown-sports/planregions/releases/tag/v0.3.0) 将对齐的二值墙体掩码转成区域实例，保留孔洞、精确标签像素面积、区域内点与显式合并操作。比较服务把两次输出的变化落实到对应组和像素去向，本地可视化报告让复核者直接定位。它可以脱离 WallGraph 独立使用，几何处理不需要神经网络模型。

模型升级复核、阈值实验、标注界面和人工修正流程，都是具体的切入点。两个包使用原图像素网格，不推断物理比例尺。PlanRegions 的空间邻近边不能证明存在门或可通行关系；没有语义证据时，房间类型保持未知。

## 工程贡献体现在哪里

这项工作将已有方法组织为独立实现、可以替换的处理阶段，并用可验证的几何约定约束结果。WallGraph 追踪骨架路径与交点，保留原图坐标。PlanRegions 保留排除像素与多边形孔洞，记录显式合并，并在不要求 ID 一致、不按最大 ID 分配矩阵的情况下比较重叠对应组。可视化报告让这些对应关系在浏览器中可检查。

贡献在工程实现与结果可检查性，不宣称提出新的基础分割算法。[方法与论文](methods.zh-CN.md)、[复现记录](reproduction.zh-CN.md)、[评测](validation.md)和[研究路线](research-roadmap.zh-CN.md)分别说明实际实现、测得结果和等待实验的假设。

## 对不足怎么说清楚

两个项目均处于实验阶段，不分发真实图纸数据集或预训练权重，公开示例由代码生成。处理真实图纸需要兼容的外部墙体模型，或者自行提供二值掩码。已发布的评测包含负面结果：新的墙体与区域完整流水线退化，可选 watershed 对预测墙体过度分割。新增可视化报告提供复核能力，没有新增识别精度结论。

比较要求两张图空间对齐。每个正值像素重叠都会参与对应关系，微小边界偏移也可能连成一个变化组。背景包含墙体、外部空间与过滤区域；仅凭两张标签图，无法判断像素为什么被排除。解释结果前，请阅读[比较使用指南](comparison.zh-CN.md)。

## 两句可以直接采用的项目定位

**WallGraph：** 把墙体掩码变成应用能用的几何结果：原图坐标中的墙线、交点与连接图，模型适配器可以替换。

**PlanRegions：** 看见两次输出之间哪些区域改变。在本地可视化报告中检查合并、分裂和消失，再接入自己的复核流程。

反馈问题时，尽可能提供最小的程序生成案例。真实图纸、标注、模型和衍生的私有报告应保留在公开仓库之外。
