# PlanRegions 能帮你做什么

[English](use-cases.md) · [快速开始](../README.zh-CN.md) · [核心方法](methods.zh-CN.md) · [实测结果](results.md)

拿到墙体掩膜后，应用常常还要回答：有哪些区域、柱子和天井有没有被算进去、合并以后面积还对不对。PlanRegions 将区域实例与像素标签图对应起来，让轮廓、孔洞、面积和后续合并有共同的依据。

## 从手头的问题开始

| 你要完成的事 | 输入 | 能拿到什么 | 还需要你提供什么 |
| --- | --- | --- | --- |
| 为图纸界面准备可选区域 | 二值墙体掩膜，可选建筑范围或分隔线 | 区域编号、带孔洞多边形、包围框和内部点 | 交互界面与人工复核 |
| 统计图像中的空间 | 区域实例标签图 | 精确的区域像素数和展示轮廓 | 换算实际面积前所需的可靠比例尺 |
| 根据复核意见合并区域 | 已保存的结果与指定编号组 | 重算后的几何、保留的排除像素和编号映射记录 | 哪些区域应归为一组的判断 |
| 给区域增加用途属性 | 对齐的类别图或兼容的外部 ONNX 模型 | 独立于几何的属性及其区域覆盖率 | 类别定义、模型或标注，以及语义评测 |
| 比较区域划分方案 | 墙体掩膜与独立的区域实例标注 | 一对一匹配的实例 F1/PQ | 固定的测试方案与失败原因分析 |
| 复核模型升级或人工编辑 | 同一原图网格上的两份实例标签 | 合并、分裂、消失等对应组，以及进出背景的像素 | 对变化是否合理的判断；评精度时仍需独立真值 |

做标注界面时，`interior_point` 提供一个确实落在区域里的像素，适合放置定位标记。普通质心可能落进天井，也可能落到凹形区域外。多边形和孔洞用于展示；像素归属与面积以 `labels.npz` 为准。这些能力可以组成界面的基础，项目本身暂不附带编辑器。

## 先独立运行，再接入墙体识别

按 [README](../README.zh-CN.md) 安装后，无需神经网络模型即可运行：

```bash
planregions demo --output runs/demo
```

程序生成的简单布局会得到 3 个区域。若接入 [WallGraph](https://github.com/crown-sports/wallgraph)，安装两个包后运行：

```bash
wallgraph demo --output runs/walls
planregions detect --walls runs/walls/walls.png \
  --wall-metadata runs/walls/walls.json --output runs/regions
```

交接时会核对尺寸、坐标和墙体像素取值。PlanRegions 输出 `regions.json`、`labels.npz`、`regions.polygons.json` 和预览图 `regions.png`。它也能读取其他来源的对齐二值墙体掩膜，无需安装 WallGraph。这个示例用于验证简单布局上的流程，不能代表真实识别精度。

## 适用边界也要说清楚

一个缺口就可能连通两个房间；外墙缺口还可能让整个内部连到图像边缘，被当作外部排除。建筑范围能限定工作区域，但不能补齐所有内部墙体。分隔线需要有依据地提供。可选分水岭在已有实测中把真实预测墙体划分得过碎，使用前应单独验证。

区域用途默认未知。邻近边只表示几何接近，不能证明有门或可以通行。多边形使用图像像素坐标，实际面积和路线规划需要额外信息。合并操作把实例归组，同时保留墙体和排除像素；它不会删除分隔墙。

[实测报告](results.md)显示，固定相同墙体输入时，两种方案的平均结果接近，尚不能确认稳定提升；换成新的墙体与区域完整流程后，结果下降。因此，验收时要分别检查墙体质量和区域划分质量。

## 30 秒介绍

> PlanRegions 把二值墙体掩膜整理成可检查、可使用的区域实例，提供像素标签、带孔洞轮廓、精确像素面积和区域内部点。它支持明确指定边界、合并区域和接入语义依据，几何处理无需神经网络模型，可以单独使用，也可以接在 WallGraph 后面。项目目前处于实验阶段，希望通过清晰的几何结果与处理约定，让别人更容易接入、测试和继续改进。

0.2.0 还可以[比较两次结果](comparison.zh-CN.md)，找出哪些区域合并、分裂或消失。这让模型改动能够追溯到具体空间，也为自动复核提供明确的触发条件。
